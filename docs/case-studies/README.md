# 공개 Next.js 프로젝트 익명 사례 연구 (2026-10-23)

이 문서는 내부 실전 검증 원본에서 대상 식별 정보를 제거한 **공개용 파생 보고서**다. 검증은 저장소 밖 격리 환경에서 했고, 외부 도입 실적이나 보안 보증이 아니다.

> **공개 정책:** 이 문서는 도구 측정값과 비식별 분류만 기록한다. 개별 보안 판정과 근거는 내부 원본에만 보존하며, 공개판은 취약점 확정이나 대상 식별 자료가 아니다.

실제 대상 이름·저장소 주소·검사 SHA·고유 경로·A–E 매핑은 Git 작업 트리 밖 내부 자료에만 있다.

## 무엇을 했나

공개된 Next.js 프로젝트 5개를 Project A–E로 익명화해, 각 프로젝트를 깨끗한 임시 디렉터리에 설치하고 프로덕션 빌드와 `kkomkkom` 검사를 수행했다. 목적은 취약점 개수 경쟁이 아니라, 도구가 내는 신호를 재현 가능한 측정값으로 남기는 것이다.

- 검증일: 2026-10-23
- 플랫폼: Linux(WSL2), Node 20·22·26 혼용
- 검사 도구: `kkomkkom` 0.1.0
- 꼼꼼 제품 코드·원격 upstream·최초 5개 복제 소스: 수정하지 않음
- 후속 disposable clone: 검사 범위 설정과 합성 payload만 추가했다가 삭제(최신 코드 동결 지시 전 수행)
- 커밋, 푸시, 배포, npm publish: 하지 않음

### 핵심 수치

- **빌드:** 5/5 성공.
- **전체 검사:** 5/5 non-strict exit 0, 모두 `coverage: incomplete`. 이는 "검사 일부 미완료"이지 보안 통과가 아니다.
- **정적 산출물:** 5/5 설정 해석 미지원(`config-wrapper`)으로 `unsupported`, `--strict` exit 1.
- **페이지 측정:** 3/5 성공, 2/5 실패. 실패 원인은 퍼센트 인코딩된 동적 라우트의 청크 경로를 도구가 찾지 못한 자체 버그다.
- **경고·정보:** 사례별 개수는 위 표와 `logs/results.json`에 있다. 개별 경고의 보안 판정은 내부에만 있다.
- **후속 검증(B):** 범위를 축소한 기준선과 무변경 비교(delta 0), 합성 500KB 증가(+55.36%, heavy), 인증 HTTP **17검사 중 16통과, 1추가검토**(근거 내부). 추가검토 항목은 보안 명세 검증 전이므로 취약점 확정으로 승격하지 않는다.

## 이 보고서가 말하지 않는 것

- "5개 프로젝트에서 취약점을 발견했다" — 아니다. 이 보고서는 개별 취약점 판정을 공개하지 않는다. 공개판은 도구 측정과 비식별 분류만 담는다.
- "도구가 모든 Next.js 앱을 지원한다" — 아니다. 정적 산출물 설정 해석, 동적 라우트 측정, 커스텀 인증 인식에서 한계가 확인됐다.
- "페이지가 900KB라 느리다" — 아니다. 도구는 비압축 파일 크기를 보고하고, 빌드 표는 gzip을 보고한다. 후속 합성 실험은 탐지 여부만 본 것이며 전송량·성능 회귀가 아니다.
- "특정 사례가 취약하다/안전하다" — 공개판은 그 판단을 하지 않는다. 개별 판정과 근거는 내부에만 있다.

## 익명성과 변경 경계

- 공개 문서에는 실제 이름·주소·SHA·고유 API 경로·헬퍼 이름·파일 경로·로그/스크린샷과 민감한 내부 상세를 넣지 않았다.
- 정확한 대상과 매핑은 저장소 밖 내부 자료에만 있으며, 이 문서만으로는 재현 신원을 확인할 수 없다.
- 공개판은 내부 원본을 덮어쓴 것이 아니라 별도로 작성한 파생물이다. 원본 수치와 판정은 내부에 보존했다.
- 변경 경계: 꼼꼼 제품 코드와 원격 upstream, 최초 5개 복제 소스는 수정하지 않았다. 후속 disposable clone에서만 검사 범위 설정과 합성 payload를 추가했다가 삭제했다. 이는 최신 코드 동결 지시 전에 수행한 별도 실험이다.
- 검증 환경과 명령의 공통 형태는 `logs/commands.md`에 남겼다. 대상별 정확한 명령은 내부 자료에만 있다.
