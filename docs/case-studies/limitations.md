# 공통 한계와 도구 이슈 (익명 공개판)

> **공개 정책:** 이 문서는 도구 측정값과 비식별 분류만 기록한다. 개별 보안 판정과 근거는 내부 원본에만 보존하며, 공개판은 취약점 확정이나 대상 식별 자료가 아니다.

이 문서는 5개 익명 사례에서 공통으로 관찰된 한계를 정리한다. 사례별 상세는 `project-a.md`~`project-e.md`에 있다.

## 1. 정적 산출물 검사 — 5/5 설정 미지원

`kkomkkom --artifacts`는 5개 사례 모두에서 Next 설정을 정적으로 해석하지 못해 `config-wrapper`로 `unsupported`를 반환했다.

- 설정이 import·함수·조건부 코드·다른 모듈 require/spread를 포함하는 경우가 많았다.
- 도구는 설정을 실행하지 않고 정적 객체로만 해석한다. 이 안전 설계는 의도된 것이지만, 실제 프로젝트 적용률을 낮춘다.
- 5개 모두 `--strict` exit 1이었고, 이는 "검사 실패"가 아니라 "미완료를 실패로 처리"한 결과다.
- 별칭 import·동적 import 사유의 `unsupported`가 다수, 한 사례는 32MiB/2,000개 상한으로 `failed`가 났다.

**결론:** 현재 artifact 검사는 이 5개 사례에서 배포 판정 근거로 쓸 수 없다. 이 사실을 "검사 통과"로 해석하면 안 된다.

## 2. 페이지 무게 측정 — 2/5 실패

두 사례는 빌드 자체는 성공했지만 페이지가 0개로 기록됐다. 원인은 도구가 동적 라우트 청크 경로를 퍼센트 인코딩된 문자열 그대로 `stat`하는 데 있다.

1. 페이지 참조 매니페스트에서 `static/chunks/...` 경로를 추출한다.
2. Next는 동적 세그먼트를 `%5B...%5D`로 인코딩해 기록한다.
3. 실제 파일은 대괄호 이름으로 존재한다.
4. 도구가 경로를 디코딩하지 않아 `missing` 측정 오류가 난다.
5. 측정 오류가 전체 페이지 맵을 비우고, 빌드 표 폴백도 실행되지 않는다.

**영향:** 동적 라우트가 있는 프로젝트에서 페이지 무게/기준선 비교가 사라진다. 사용자는 "페이지 0개"를 보게 된다.

**개선 제안(구현하지 않음):** 청크 경로를 안전하게 디코딩하거나, 측정 오류 시 빌드 표 파싱으로 폴백한다. 둘 다 회귀 테스트가 필요하다.

## 3. 페이지 무게는 raw 파일 크기다

`manifest-file` 측정은 gzip/brotli 전송 크기가 아니라 `.next` 안의 JS 파일 크기 합이다. 한 사례에서 도구는 약 0.9MB로, 빌드 표는 약 0.23MB로 보고했다. 약 4배 차이는 압축 때문이다.

- 도구 수치를 빌드 표와 직접 비교하지 말 것.
- "900KB 페이지"를 "전송 900KB"로 해석하지 말 것.
- 기준선도 같은 방법(`manifest-file`)일 때만 delta를 비교할 수 있다.

## 4. 기준선 — 최초 검사와 후속 검증 구분

최초 5개 검사는 `--update`를 실행하지 않았다. 따라서 모든 페이지가 `comparable:false`, `heavy:false`이고 "느려졌다/빨라졌다" 판정은 없다.

후속 B에서만 범위를 축소해 기준선을 만들고 무변경 비교와 합성 증가를 확인했다. 이 결과는 최초 5개 결과와 별도 표에 기록했다.

- 범위 축소: 스트림·프록시 계열 4개 패턴을 `ignoreRoutes`로 제외했다.
- `coverage: complete`는 검사 실행 범위를 뜻하며, 제외 경로와 기존 finding이 해결됐다는 뜻이 아니다.
- 무변경 비교는 delta 0이었다. 최초 보고서와 일부 바이트 차이가 있어 원본 수치는 덮어쓰지 않았다.
- 합성 500KB 증가는 `/`에서 +500,119B(+55.36%), `heavy:true`로 탐지됐다. 실제 취약점/전송량/성능 회귀가 아니다. 합성 문자열이 공유 청크에 들어가 4개 페이지가 모두 같은 양만큼 증가했다.

## 5. 동적 라우트 페이지 스모크 — `sample-missing`

경로 파라미터가 있는 페이지는 샘플 값이 없으면 페이지 스모크를 실행하지 못한다. 여러 사례에서 `sample-missing`/`sample-unsupported`가 발생했다. 애플리케이션 5xx가 아니라 도구 입력 한계다.

## 6. 커스텀 인증 래퍼를 인식하지 못함

도구의 정적 분석은 알려진 인증 패턴을 중심으로 한다. 커스텀 인증 래퍼는 인증 신호로 인식되지 않아 `write-no-auth`/`write-unsupported`가 발생했다.

공개판은 어느 사례가 실제 검토 대상인지 분류하지 않는다. 개별 판정과 근거는 내부 원본에만 있다. 오탐과 실제 검토 항목이 섞여 있을 수 있으므로, 도구 경고만으로 배포 여부를 결정하면 안 된다.

## 7. 환경 의존 실패

다음은 코드 문제가 아니라 격리 환경의 제약이다.

- 비밀번호 미설정으로 보호 API가 503.
- 외부 소스 7개 503.
- Docker/Kubernetes 소켓 없음 → 500.
- 외부 인증·DB 환경 변수 없음 → 500.
- 관리자/접근 코드 미설정 → 403, 일반 API 조건부 허용.
- 뉴스레터 제공자 미설정 → 308만 관찰, 실제 가입 요청은 보내지 않음.

이 실패를 "취약점" 또는 "빌드 실패"로 집계하지 않았다. 실제 배포 환경에서는 값과 외부 연결이 달라질 수 있다.

## 8. HTTP 검증의 범위

- `kkomkkom`은 GET만 프로브한다. 쓰기 경고는 정적 분석 결과이며 실제 POST/PUT/PATCH/DELETE를 보내지 않는다.
- 최초 검사에서는 한 사례만 빌드 서버를 띄워 실제 GET 4건을 확인했다.
- 후속 B에서 loopback 인증 HTTP 검사를 수행했다. **17검사 중 16통과, 1추가검토**(근거 내부). 추가검토 항목은 보안 명세 검증 전이므로 취약점 확정이 아니다.
- 유효한 외부 검색·게시·쓰기, 권한 상승, SSRF, 레이트리밋, CSRF/CORS 공격 테스트는 하지 않았다.
- 인증 관련 원문은 출력·보존하지 않았다.

## 9. 설치 스크립트 사전 검토

- 설치·빌드 스크립트의 사전 검토 기록은 보존되어 있지 않으며, 검토의 충분성은 검증되지 않았다.
- `npm ci --ignore-scripts`는 설치 스크립트를 건너뛴다는 뜻이지, 프로젝트의 `npm run build` 자체가 안전하다는 증거가 아니다.
- 사후 확인을 사전 검토로 소급하지 않는다.

## 10. 플랫폼·배포 범위

- Linux(WSL2)만 검증했다. Windows/macOS, Docker, Kubernetes, Vercel/Cloudflare 배포는 미검증.
- Node 20/22/26만 사용했다. Node 24는 이번 5개 사례에 쓰지 않았다.
- `output: "standalone"`, 모노레포, 커스텀 `distDir`는 artifact 검사에서 다루지 못했다.
- 프로덕션 서버를 실제 도메인/TLS/리버스 프록시 뒤에 두고 검증하지 않았다.

## 11. 라이선스

대상에는 permissive와 copyleft 라이선스가 섞여 있다. 이 검증은 최초 5개 clone의 소스를 수정하지 않았고, 후속 disposable clone에서만 검사 범위 config와 합성 payload를 추가했다가 삭제했다. 꼼꼼 제품 코드와 원격 upstream을 재배포하지 않았다. 향후 코드를 재사용하거나 파생물을 배포할 때는 각 라이선스 의무를 별도로 검토해야 한다. 이 보고서는 법률 검토가 아니다. 대상별 라이선스 매핑은 내부 원본에만 있다.

## 12. 변경 경계와 보고서의 지위

- 꼼꼼 제품 코드·설정·의존성과 원격 upstream은 수정하지 않았다.
- 최초 5개 복제 소스는 수정하지 않았다.
- 후속 disposable clone에서만 검사 범위 설정과 합성 payload를 추가했다가 삭제했다. 최신 코드 동결 지시 전에 수행한 별도 실험이다.
- 이 디렉터리는 공개용 **익명 파생 보고서**다. 실제 이름·주소·SHA·고유 경로와 민감한 내부 상세가 담긴 원본과 매핑은 저장소 밖 내부 자료에 있다.
- 원본은 byte-exact로 보존했고, 공개 문서는 원본을 덮어쓴 것이 아니다.
- 원본 클론과 `node_modules`, `.next`는 저장소 밖 `$WORK`에 있었고, 보고서 확정 후 삭제했다.
- 수치와 판정은 2026-10-23의 특정 환경에 한정된다.
