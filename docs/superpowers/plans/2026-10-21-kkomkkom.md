# 꼼꼼 (kkomkkom) 구현 계획

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Next.js 앱의 안 잠긴 API 라우트와 무거워진 페이지를 커밋 전에 찾아내는 CLI를 만든다.

**Architecture:** 프레임워크 없이 TypeScript + Node 표준 라이브러리만 쓴다. 파일 시스템에서 라우트를 찾고, 개발 서버를 띄워 GET만 호출하고, `next build` 출력에서 전송량을 읽는다. 판정·기준선·리포트를 각각 분리해 단위 테스트한다.

**Tech Stack:** Node 20+, TypeScript, `node:test`, `node:util.parseArgs`. 런타임 의존성 0개.

**Spec:** `docs/superpowers/specs/2026-10-21-kkomkkom-design.md`

## Global Constraints

- 런타임 의존성 0. devDependency는 typescript, @types/node만.
- GET 외 메서드는 절대 보내지 않는다.
- localhost 외 URL은 거부한다.
- 쿠키/인증 헤더를 보내지 않는다.
- 브라우저를 쓰지 않는다.
- Node 20 이상.

## Review Focus

- 개발 서버가 이미 떠 있는데 우리가 죽여버리는 경우 → 소유권 표시로 방지하고 테스트한다.
- 동적 라우트 `[id]`에 값을 넣지 않고 호출해 404를 "잠김"으로 오판하는 경우 → unknown으로 처리.
- `next build` 출력 형식이 버전마다 달라 파싱이 깨지는 경우 → 못 읽으면 조용히 건너뛰고 경고.
- 200이지만 빈 본문/HTML 오류 페이지인 경우 → 상태 코드만으로 exposed 판정하지 않는다.
- 기준선 파일이 깨졌을 때 프로그램이 죽는 경우 → 백업 후 새로 시작.
