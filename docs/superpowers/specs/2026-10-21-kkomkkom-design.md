# 꼼꼼 (kkomkkom) — 설계 문서

날짜: 2026-10-21
상태: 승인됨 (사용자 "개발 진행해")

## 한 줄 정의

Next.js 앱을 커밋하기 전에 **안 잠긴 API 문**과 **무거워진 페이지**를 찾아주는 CLI.

## 누구를 위한 것인가

- AI로 앱을 만드는 사람: 코드가 맞는지 AI에게 다시 물어보는 대신 증거를 얻는다.
- 주니어 개발자: 손으로 테스트를 안 써도 변경의 영향을 확인한다.

## v1에서 하는 일

1. Next.js 프로젝트를 찾아 개발 서버를 띄운다.
2. API 라우트와 페이지 라우트를 자동으로 찾는다.
3. **인증 검사** — API 라우트를 로그인 없이 호출해 실제로 열려 있는지 본다.
4. **무게 검사** — `next build` 결과에서 페이지별 First Load JS를 읽어 지난번과 비교한다.
5. 결과를 사람이 읽는 형태로 보여주고, `.kkomkkom/baseline.json`에 기준을 저장한다.
6. 새로 뚫린 문이 있으면 종료 코드 1로 끝난다.

## v1에서 하지 않는 일 (명시적 제외)

- POST/PUT/PATCH/DELETE 요청을 **절대 보내지 않는다**. 데이터를 지울 수 있기 때문.
- 브라우저를 쓰지 않는다. Playwright/Chrome 설치 없이 동작해야 한다.
- 코드를 고쳐주지 않는다. 찾아서 알려주기만 한다.
- AI 요약을 넣지 않는다. v1.1에서 붙인다.
- Next.js 이외의 프레임워크는 지원하지 않는다.

## 명령

```
kkomkkom               # 인증 검사 + 빌드/무게 검사
kkomkkom --fast        # 인증 검사만 (빌드 생략)
kkomkkom --json        # 기계가 읽는 출력
kkomkkom --update      # 현재 상태를 새 기준선으로 저장
kkomkkom --port 3100   # 개발 서버 포트 지정
```

## 인증 검사 규칙

라우트마다 판정은 하나다.

| 관찰 | 판정 | 표시 |
|---|---|---|
| 401 또는 403 | 잠김 | 🟢 |
| 3xx (로그인으로 이동) | 잠김 | 🟢 |
| 200 + 소스에 인증 코드 있음 | **뚫림** | 🔴 |
| 200 + 소스에 인증 코드 없음 | 확인 필요 | 🟡 |
| 200 + `ignoreRoutes`에 있음 | 공개 | (숨김) |
| 404, 405 | 확인 불가 | ⚪ |
| 5xx | 서버 오류 | ⚠️ |
| 연결 실패/타임아웃 | 확인 불가 | ⚪ |

인증 코드 신호(소스 검색): `auth(`, `getServerSession`, `getToken`, `verifyToken`, `requireUser`, `currentUser`, `cookies()`, `headers().get('authorization')`.

**핵심 판정은 🔴이다.** "코드에는 잠금장치가 있는데 실제로는 열려 있다"는 뜻이라, 미들웨어 우회 같은 진짜 사고를 잡는다. 🟡는 소음이므로 실패로 치지 않는다.

동적 라우트(`[id]`)는 실제 값을 모르면 호출하지 않고 ⚪로 둔다. `kkomkkom.config.json`의 `sampleParams`로 값을 줄 수 있다.

## 무게 검사 규칙

- `next build` 출력에서 `First Load JS` 값을 파싱한다.
- 기준선 대비 **+15% 그리고 +30KB**를 동시에 넘으면 🐢 경고.
- 경고는 종료 코드에 영향을 주지 않는다.
- v1은 초 단위 체감 속도를 재지 않는다. 측정 노이즈 때문이며, 대신 정확한 전송량을 보여준다. TTFB/LCP는 v1.1.

## 기준선

`.kkomkkom/baseline.json`

```json
{
  "version": 1,
  "createdAt": "2026-10-21T00:00:00.000Z",
  "routes": {
    "/api/users": { "verdict": "exposed" },
    "/api/health": { "verdict": "public" }
  },
  "pages": {
    "/checkout": { "firstLoadJs": 180000 }
  }
}
```

비교 결과는 `new`, `fixed`, `same`, `changed` 네 가지로 나눈다. 기준선이 없으면 전체를 보여주고 저장한다.

## 설정 파일

`kkomkkom.config.json` (없어도 동작)

```json
{
  "ignoreRoutes": ["/api/health", "/api/webhooks/*"],
  "sampleParams": { "/api/orders/[id]": { "id": "1" } },
  "port": 3100,
  "thresholds": { "jsPercent": 15, "jsBytes": 30000 }
}
```

## 안전 규칙

- 대상은 `localhost`만. 외부 URL은 거부한다.
- 쿠키와 인증 헤더를 보내지 않는다.
- GET만 보낸다. 그 외 메서드는 소스 정적 분석만 한다.
- 서버는 우리가 띄운 것만 종료한다. 이미 떠 있던 서버는 건드리지 않는다.

## 오류 처리

- Next.js 프로젝트가 아니면 안내 후 종료 코드 2.
- 개발 서버가 60초 안에 뜨지 않으면 안내 후 종료 코드 2.
- 빌드 실패는 최상단에 크게 표시하고 종료 코드 1.
- 개별 라우트 실패는 전체를 멈추지 않는다.

## 테스트

- 단위: 라우트 탐색, 인증 신호 탐지, 빌드 출력 파서, 기준선 비교
- 통합: 가짜 HTTP 서버로 판정 규칙 검증
- 수동: `fixtures/`의 작은 Next.js 앱에 실제 실행

## 위험

- Next.js가 공식적으로 비슷한 기능(개발 루프 검증)을 넓히고 있다. 기준선 비교와 커밋 전 전수 검사가 우리 자리다.
- 인증 판정은 소스 신호에 의존하므로 오탐이 가능하다. 🔴만 실패로 처리해 소음을 줄인다.
