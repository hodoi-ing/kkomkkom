# 이슈 #2: Next 배포물 점검과 제한된 보호 적용

## 전제·진행 권한

요구사항은 https://github.com/hodoi-ing/kkomkkom/issues/2 이다. 사용자는 추가 승인 없는 개발/검수/GitHub 반영과 로컬 동기화를 승인했으며 공개 전환·배포는 금지했다. #1의 검사 근거/coverage/종료 계약을 통과시킨 뒤 아래 단계를 순차 구현한다. 탭1 총괄이 설계와 검수를, Herdr 탭 `2`가 구현을 맡는다.

문서에 적힌 보류를 개발 승인으로 해제하지 않는다. 에이전트별 설치·연결검증은 보류하며 MCP 서버의 자동 검증만 한다. 난독화·Electron·모바일 구현은 수요/환경/유지비가 미확정이므로 후보 평가만 기록한다. 상시 서버·계정·GUI·클라우드·플러그인 플랫폼을 만들지 않는다.

## 선택한 접근과 대안

기존 엔진의 별도 opt-in 산출물 검사 모드를 추가한다. 기본 fast/HTTP 동작을 조용히 바꾸지 않고, 빌드/서버가 필요 없는 정적 산출물 점검은 단독 실행할 수 있다. 별도 바이너리나 모든 프레임워크 추상화는 필요 없다. 첫 버전은 기본 Next 출력 경로만 지원하며 실제로 해석하지 못한 custom distDir/export/standalone/모노레포를 지원 성공으로 표시하지 않는다.

대안인 기본 검사에 모든 파일 분석을 끼우는 방식은 fast 의미와 비용을 바꾼다. 별도 대형 보안 엔진은 초기 설치 부담에 맞지 않는다. 따라서 같은 rule/evidence/coverage 엔진에 작은 opt-in 분기만 추가한다. 정확한 CLI 옵션과 공개 타입은 단계별 구현 계획에서 고정하며 중복 엔진을 만들지 않는다.

## 공통 결과와 지원 경계

각 결과는 stable rule ID, 프로젝트 상대 파일/위치, severity, 관찰 근거, 확인 범위, 불확실성, 조치 방향을 가진다. 실제 비밀값/개인 절대경로/환경값은 포함하지 않는다. #1의 CLI·JSON·MCP schemaVersion/coverage/종료 계약과 5개 언어를 그대로 사용한다.

rule ID를 가진 예외는 해당 경로와 이유를 필수로 요구한다. 예외는 결과/coverage에 남기며 보호 정책 자체를 제거하지 않는다. 잘못된 규칙/비어있는 사유/과도하게 넓은 경로는 필드별 오류로 거부한다. 기본 ignore와 새 rule 예외의 의미를 구분한다.

탐색 경계는 프로젝트의 `public`과 기본 production 클라이언트 산출물 `.next/static`이다. `.next/server`는 비공개 서버 산출물로 구분한다. 루트 `.next` 유무만으로 최신 빌드라 단정하지 않고 BUILD_ID/파일 시간 등 관찰 가능한 fresh/stale/unknown 근거를 기록한다. 새 빌드는 명시 선택할 때만 수행한다. symlink와 경로 traversal로 허용 경계 밖을 읽거나 HTTP origin을 벗어나지 않는다. 파일당 기본 1 MiB, 검사 전체 32 MiB, 파일 수 2000개를 상한으로 두고 초과·권한오류·읽기실패를 coverage에 남긴다. 숨김파일도 배포 경계 안에서는 대상이다. 리포지토리 전체의 테스트 폴더를 무조건 경고하지 않는다.

## 단계 0: 실측 기준선

코드 크기를 설치 크기로 환산하지 않는다. `npm pack` 압축/자체 파일 크기, production dependency 설치 디스크/다운로드 근거, 정적 검사/HTTP 검사/빌드 포함 검사 각각의 시간, 최대 RSS, 기본/AI/설치 네트워크 사용을 문서화한다. 환경(Node/OS/fixture/측정명령/캐시 여부)을 함께 남긴다. 네트워크 다운로드를 실측하지 못하면 미측정이라 기록한다. 파서 추가 전·후와 산출물 기능 추가 전·후를 구분한다. 측정된 결과로 비용 증가를 판단하고 임의의 1초/0MB 예산을 약속하지 않는다.

## 단계 1: 배포물 정적 검사

### 소스맵

기본 클라이언트 산출물의 `.map`, `sourceMappingURL` 참조와 inline data map을 찾는다. 설정의 productionBrowserSourceMaps, 실제 파일, 참조, 로컬 HTTP 응답은 별도 증거다. Next 설정을 분석하려고 실행/import하지 않는다. 정적으로 해석할 수 없는 설정은 unknown이다. `.next/server`의 map이나 오류 추적 업로드용 비공개 위치를 공개 확정으로 보고하지 않는다. 파일 존재만으로 외부 공개를 확정하지 않는다.

### 배포 파일·개발 흔적

실제 public/클라이언트 제공 경계의 `.env`, 백업/설정/로그/테스트 자료를 파일명 의심과 내용 확인으로 구분한다. 서버 전용 파일·저장소에만 있는 정상 테스트는 경고하지 않는다. 운영 로그에 비밀정보가 확인되면 값 자체를 내보내지 않고 rule/위치/마스킹된 근거만 제공한다.

### 클라이언트 비밀정보·서버 경계

기존 비밀정보 패턴과 마스킹을 재사용해 실제 클라이언트 번들에서 고신뢰 비밀 패턴과 이름 기반 신호를 구분한다. 공개키·공개 설정·예제값은 키워드 하나로 유출 확정하지 않는다. 같은 원인/파일/위치는 rule ID와 증거를 병합한다.

`use client` 출발점에서 확인 가능한 로컬 정적 import를 제한적으로 따라가 `server-only`, 서버 DB/인증정보 모듈 혼입 가능성을 보고한다. 단순 문자열은 실행/import 증거가 아니다. 외부 alias/동적 import/해석 불가 graph는 미검증 범위로 남긴다. 새 빌드가 server-only 혼입을 거부하면 그것도 별도 빌드 증거이며 실제 배포 유출로 부르지 않는다. 수정은 서버 분리/응답 최소화/비밀 제거이며 난독화가 해결책이라고 하지 않는다.

## 단계 2: 검증과 선택적 로컬 production HTTP

운영 서버 확인은 명시적 opt-in에 한해 loopback의 사용자가 선택한 서버에 GET만 보낸다. 외부 호스트·userinfo·쿠키·Authorization은 허용하지 않고 리다이렉트는 자동으로 따라가지 않는다. 파일명 의심과 HTTP 공개 확인을 구분하며, 검사 대상 내용/파일과 응답이 일치하는 근거가 없으면 단순 200을 해당 파일 노출로 확정하지 않는다(SPA fallback도 구분). 바이트/시간 상한과 본문 취소를 공유한다. 기존 dev probe를 production 증거로 재활용하지 않는다. 빌드 ID를 신뢰할 수 없으면 대상 동일성 미확인이라고 명시한다.

정상 map 없음/비공개 map/inline map/공개 map/설정-산출물 불일치, 저장소에만 있는 테스트/public 민감 파일, 정상 공개키/가짜 비밀값, 없는 산출물/미지원 출력/대형 파일/읽기실패를 fixture로 구분한다. 실제 Next production build와 pack 소비자 CLI/MCP 호출을 검증한다. stdout/stderr/JSON/MCP/설명 입력의 비밀값 비노출도 확인한다. 비용과 OS별 실제 검증 범위를 기록한다.

## 단계 3: 제한된 보호 적용

제품의 일반 검사와 MCP 검사 호출은 읽기 전용으로 유지한다. 보호는 별도의 명시 명령으로 preview → apply → build/관련 smoke·재검사 → 복원 정보를 제공한다. 개발 작업 승인은 사용자의 다른 앱에 보호를 적용할 권한이 아니다. 자동 테스트는 임시 fixture만 수정한다.

첫 자동 수정은 정적으로 확인 가능한 Next 설정의 직접 리터럴 `productionBrowserSourceMaps: true`를 `false`로 바꾸는 작은 작업에 제한한다. 전체 소스맵 삭제/항상 끄기/임의 설정 실행/문자열 치환/전역 hooks·설정 변경은 하지 않는다. wrapper·복수 설정·계산식·export 분기 등 안전하게 한 속성을 특정할 수 없는 형식은 미지원과 수동 diff 안내로 끝낸다. 서버 비밀 보호나 역분석 방지라고 설명하지 않으며 오류 추적 진단 영향도 preview에 표시한다.

preview는 파일과 정확한 diff, 효과/한계, 빌드 산출물 생성, 의존성 추가 없음/자동 다운로드 없음, 오류 추적 영향, 복원 방법을 표시한다. 기본은 preview이며 실제 apply는 명시 플래그로만 가능하다. CI에서 승인 대기하지 않고 명시적 선택 없이는 거부한다. 지원하지 않는 추가 도구 설치는 하지 않는다.

apply 직전 파일 hash/기존 Git dirty 여부를 확인한다. 미커밋 변경이 있는 대상 파일은 거부하고, diff 승인 후 파일이 바뀌면 재-preview를 요구한다. 원본을 `.kkomkkom` 아래 고유 transaction으로 보존하며 프로젝트 밖 symlink/경로를 거부한다. 설정을 원자적으로 교체하고 실패 상태를 숨기지 않는다. 복원도 적용 이후 파일 hash와 일치할 때만 수행해 사용자 후속 변경을 덮어쓰지 않는다.

적용 후 로컬 Next production build, 대상 소스맵 검사, loopback production smoke를 수행하고 실패하면 적용/검증 실패와 복원 상태를 분리한다. 검증 실패 시 안전한 hash 조건에서 원본 복원을 시도하고 복원 실패도 명시한다. 초기 버전은 소스맵 설정 변경만 제공하며 민감 파일 삭제/앱 변환/난독화는 제공하지 않는다.

## 단계 4: 확장 평가 기록

난독화는 번들·성능·오류 추적 비용이 있고 비밀 보호 대체제가 아니다. Electron은 버전/OS/기능 충돌 검증이, Android/iOS는 실제 빌드/서명 환경이 선행되어야 한다. 현재 수요/환경/유지보수 주체가 없으므로 구현/설치는 하지 않고 재개 조건을 문서에 남긴다. 이 단계의 후보 평가 완료를 해당 플랫폼 지원 완료로 표현하지 않는다.
