## 선택한 접근

기존 탐색 → HTTP/정적 감사 → 빌드 → 비교 → 보고서 엔진을 유지한다. 인증 함수 흔적과 HTTP 관찰, 명시 정책, 검사 완료 여부를 별도 데이터로 보존하고 CLI/JSON/MCP가 동일 결과를 사용한다. 자체 렉서 패치를 늘리는 대신 설치된 TypeScript의 AST를 제한적으로 사용한다. 런타임에 쓰는 파서는 production dependency로 명시하고 pack/install 비용을 실측한다. 새 플러그인 플랫폼이나 대형 프레임워크를 도입하지 않는다.

대안인 정규식 패치 확대는 메서드 경계를 신뢰하기 어렵고, 전면적인 프로그램 분석은 이번 제품 범위와 설치 비용에 맞지 않는다. AST도 인증의 강제를 증명하지 않으며 wrapper/외부 재수출/불명확한 분기는 미확인으로 남긴다.

## 접근 정책·메서드 분석

설정의 `routePolicies`는 발견된 경로 템플릿(예: `/api/orders/[id]`)에서 HTTP 메서드별 `public` 또는 `protected`를 지정하는 선택적 객체다. 정책 미지정은 별도의 상태이며 정적 인증 흔적 유무로 보호 정책을 만들어내지 않는다. 유효하지 않은 메서드/정책은 필드명을 포함하는 설정 오류다. 첫 버전은 정확 경로 매칭으로 제한한다.

App Router의 함수/변수 export, 로컬 alias export를 메서드별로 분석한다. `pages/api`는 명확한 req.method 비교와 switch 분기를 지원하고 공통 가드 또는 흐름이 불명확하면 미확인으로 표시한다. 문자열/주석/정규식/호출하지 않는 중첩 함수의 흔적을 핸들러 인증 실행 증거로 사용하지 않는다. 지원하지 않는 wrapper/re-export를 인증 없음 확정으로 취급하지 않는다.

익명 GET의 성공은 관찰 사실이다. 명시 `protected` + 2xx만 보호 정책 위반으로 `exposed`를 부여하며 빈 응답도 예외로 숨기지 않는다. `public`의 정상 성공은 공개 결과, 미지정 성공은 검토 신호다. 401/403과 확인된 동일 origin 로그인 리다이렉트는 기존 거부 관찰을 유지한다. 오류 화면은 정상 정책 검사 성공이 아니다. 쓰기 메서드는 정적 검사만 수행하며 요청하지 않는다.

결과에는 요청 메서드, HTTP 상태, 선택 정책, 정적 인증 분석 상태를 보존한다. HTTP 상태만으로 데이터 유출을 확정하지 않는다. 샘플 경로는 같은 로컬 origin을 벗어나거나 쿼리/fragment로 해석되지 않도록 세그먼트 인코딩/검증한다.

## 검사 범위·종료 계약

검사 항목별로 rule ID, 경로/메서드, 상태(`checked`, `static-only`, `ignored`, `skipped`, `failed`, `unsupported`)와 사유를 기록한다. 집계와 전체 `complete`/`incomplete`/`empty`를 동일 엔진에서 계산한다. API뿐 아니라 페이지 timeout, 동적 파라미터 누락, 미측정 JS도 반영한다. 명시적 제외, fast 빌드 생략, POST-only의 GET 미지원은 각각 이유를 표시한다. 모든 항목 제외 또는 유의미한 검사 없음은 통과 배너를 내지 않는다.

종료 코드는 0=검사 범위의 차단 문제 없음, 1=발견 문제 또는 strict 위반, 2=설정/환경/도구 실행 오류다. strict에서는 필수 검사 누락과 경고도 1이다. coverage와 종료 코드는 별도 필드로 공개한다. JSON에 `schemaVersion: 2`를 추가하며 기존 diff/extra 필드는 가능한 한 유지한다. MCP도 text뿐 아니라 같은 구조 결과를 제공한다. 5개 언어 필수 메시지에서 전역 배포 안전 보장을 제거한다.

## 프로세스·입력·크기·기준선

- 프로젝트에서 resolve한 Next CLI를 `process.execPath`로 직접 실행한다. 자동 npx 다운로드나 문자열 shell 명령을 사용하지 않는다. 직접 띄운 서버에 `--hostname 127.0.0.1`을 지정한다.
- spawn error/조기 종료/준비 timeout/사용자 중단을 구분하고 마스킹된 오류로 전달한다. 소유 프로세스만 종료하며 종료 확인과 제한된 강제 종료를 사용한다. 재사용 서버의 프로젝트 신원 미확인을 결과에 표시한다.
- 설정/기준선/MCP 입력은 null/배열/객체, 메서드/판정, port 1~65535, 유한 비음수 임계값/바이트, sampleParams 문자열을 검증한다. 누락 파일과 권한/읽기 오류를 구분한다. 손상된 기준선은 제자리 보존하고 명시적 오류로 반환한다.
- B/kB/MB를 1/1000/1000000으로 변환한다. chunk 누락/읽기 오류는 미측정이지 0이 아니다. 실제 0바이트와 중복 chunk를 검증한다. 파일 합계/Next 출력 표의 서로 다른 측정 방식은 메타데이터로 구분하고 직접 비교하지 않는다.
- 일반 검사와 최초 검사는 기준선을 쓰지 않는다. `--update`만 생성/갱신하며 fast는 기존 크기를 보존한다. 실패/필수 누락 상태의 update는 기준선을 덮어쓰지 않는다. 임시 파일+rename 및 배타적 쓰기 잠금으로 중복 저장 손상을 막고 잔여 파일을 정리한다.

## 검수 경계

임시 로컬 fixture만 사용하며 GET-only, 쿠키/Authorization 미전송을 지킨다. MCP tools/call 정상/잘못된 입력/프로젝트 오류, 실제 Next build/manifest, npm pack 소비자 설치 CLI/MCP를 검증한다. 비밀값이 stdout/stderr/JSON/MCP/설명 입력에 나오지 않는지 검증한다. Windows/macOS 미검증을 명시하며 Linux/WSL 성공으로 확대하지 않는다. 전체 에이전트 설치/연결검증, TTFB, 배포와 공개 전환은 하지 않는다.
