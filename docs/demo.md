# 꼼꼼 README 데모 영상 가이드

목표는 처음 보는 개발자가 30~40초 안에 **어디서 실행하고, 어떤 근거를 얻고, 다음에 무엇을 확인하는지** 이해하게 만드는 것입니다. 기존 영상은 아래 기준과 다른 부분만 편집합니다.

## 현재 상태

2026-10-22 확인한 main 파일·릴리스·이슈 댓글에서는 기존 영상 파일이나 첨부 URL을 찾지 못했습니다. 기존 영상을 보지 못한 상태이므로 재촬영 필요 여부는 아직 판단하지 않았습니다. README에는 실제 보고서 렌더러에 예시 데이터를 넣은 SVG를 먼저 배치했습니다.

## 권장 편집 구성

| 시간 | 화면 | 전달할 내용 |
|---|---|---|
| 0~4초 | 이름과 짧은 설명 | “Next.js 배포 전, 확인할 문제를 찾아주는 CLI · MCP” |
| 4~10초 | 테스트용 Next.js 프로젝트 터미널 | `kkomkkom --fast --lang ko` 실행. CLI 연결 전이라면 빌드한 `dist/cli.js` 경로로 실행 |
| 10~22초 | 실제 결과를 확대 | 파일·라우트·상태를 읽을 수 있게 보여주고, 확인할 항목 한두 개만 강조 |
| 22~32초 | 사람이 근거를 확인하는 화면 | 공개 API인지·인증이 적용되는지 확인하거나, 테스트용 `.env`가 git 추적 대상인지 확인 |
| 32~40초 | 마무리와 README 시작 안내 | “결과를 검토하고, 수정 후 다시 검사하세요.” |

시간은 편집 권장값이며 실제 검사 성능을 뜻하지 않습니다. 대기를 잘랐다면 “대기 구간 편집”을 표시하세요. 설치 과정은 본문 빠른 시작에 맡기고 영상에서는 생략해도 됩니다.

## 기존 영상에서 확인할 부분

- [ ] 첫 5초 안에 Next.js 대상 검사 도구임이 드러나는가?
- [ ] 명령과 결과를 읽을 수 있는가? 1280×720 이상 화면을 권장하되 모바일에서도 확인한다.
- [ ] `--fast` 영상에서 빌드·JS 크기를 새로 측정했다고 설명하지 않는가? 크기 비교를 보여주려면 일반 실행과 이전 기준선이 필요하다.
- [ ] 실제 실행 결과를 쓰고, 연출용 데이터·잘라낸 대기 구간을 구분하는가?
- [ ] 실제 토큰·개인정보·운영 데이터 대신 임시 프로젝트와 가짜 값을 사용하는가? 도구의 마스킹만 믿지 말고 영상도 직접 확인한다.
- [ ] “200이면 취약점”, “통과하면 안전”, “자동으로 수정”, “역분석 차단 완료” 같은 표현이 없는가?
- [ ] 현재 npm 미공개 상태에서 `npx kkomkkom`으로 설치되는 것처럼 보이지 않는가?
- [ ] 에이전트 화면은 실제 연결 검증을 재개한 뒤 추가하는가? 현재는 CLI 시연을 우선하며 지원 로고만으로 호환성을 보장하지 않는다.
- [ ] 추가 보호 기능을 이미 구현된 기능처럼 소개하지 않는가?

## README에 넣는 위치

README의 `DEMO_VIDEO` HTML 주석 바로 아래, 결과 이미지 위에 넣습니다. 파일을 확보한 뒤 GitHub 편집 화면에 영상을 첨부하고, GitHub가 만들어 주는 첨부 URL 또는 삽입 내용을 사용합니다. 현재는 실제 URL이 없으므로 재생되지 않는 임시 링크를 만들지 않습니다.

반영 후 데스크톱·모바일 README에서 재생과 접근 권한을 확인하세요. 비공개 저장소라면 저장소 접근 권한이 없는 사람에게 공개 데모처럼 안내하지 않습니다. 영상 접근성을 확인한 뒤 필요하면 기존 결과 이미지를 접거나 영상 아래 보조 자료로 유지합니다.

큰 원본 영상·편집 프로젝트를 기본 소스 다운로드에 포함하지 않는 방향을 권장합니다. README에는 짧은 데모를 연결하고, 편집 원본은 별도로 관리하세요.
